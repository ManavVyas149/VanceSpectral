This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

VanceSpectral is a JUCE-based audio plugin (`projectType="audioplug"` in `Vancespectral.jucer`) — a spectral sample-playback synth with waveform/spectrogram-based region editing, ADSR envelopes, pitch/timbre shifting, and a preset/history system. It builds as VST3, AAX, CLAP, AU (macOS) and Standalone, is a MIDI-driven synth instrument (`pluginIsSynth`, `pluginWantsMidiIn`), and targets C++20.

## Architecture

### Processor / Engine split
- `PluginProcessor` (`VancespectralAudioProcessor`) is the JUCE `AudioProcessor` entry point. It owns the `AudioProcessorValueTreeState` (`apvts`, parameter layout defined in `createParameterLayout()`), a `SampleEngine`, and a `HistoryManager`, and exposes thin pass-through methods (`noteOn`, `setRegion`, `setFrequencyFilterBands`, etc.) that forward to `SampleEngine`. It does not do DSP itself.
- `SampleEngine` (`Source/SampleEngine.h/.cpp`) is the real audio engine: a polyphonic (up to `MAX_VOICES = 32`) sample player with per-voice state (`Voice` struct) covering amplitude/filter ADSR (via `EnvelopeData`), pitch/timbre shifting (three `PitchMode`s: Stretch/WSOLA, Resample, Axial), five `PlaybackMode`s (Forward/Backward/Forw-Backw/Back-Forw/Random), per-voice spectral-region bandpass filtering (`VoiceRegionFilter`, cascaded `juce::IIRFilter`s), glide, and an exciter. All engine state is `std::atomic` so UI-thread setters (`setPitchMode`, `setRegion`, etc.) are safe to call from the editor while `process()` runs on the audio thread.
- Region/frequency selections drawn in the UI become `SpectralRegion` / `FrequencyBand` structs passed down to `SampleEngine::setSpectralRegions` / `setFrequencyFilterBands`, which pre-filter the loaded sample (`updateFilteredSample()`) rather than filtering per-sample at playback time.

### Editor / UI
- `PluginEditor` (`VancespectralAudioProcessorEditor`) composes the UI from components in `Source/`: `PresetBarComponent`, `ToolbarComponent`, `SpectrogramComponent`, `SegmentedControlComponent` (used for playback-mode and pitch-mode selectors), `ADSRPanel`, and `PresetBrowserOverlay`. Parameter bindings mostly go through `apvts` attachments (e.g. `SliderAttachment` for volume); the segmented controls sync via `juce::ParameterAttachment`.
- `SpectrogramComponent` is the main interactive surface: it owns the loaded `AudioBuffer<float>`, renders the waveform/spectrogram image, handles file drag-and-drop (`FileDragAndDropTarget`), and lets the user draw/resize/move rectangular time-frequency `SelectionRegion`s with a tool (`ToolType`, defined in `ToolbarComponent.h`) that become the spectral regions fed back into the processor.
- `SpectralUILookAndFeel` centralizes the plugin's custom `LookAndFeel` (colours, fonts) — UI components pull colours/fonts as static members from it (e.g. `SpectralUILookAndFeel::accentColour`) rather than hardcoding.
- Custom-painted buttons (e.g. `PluginEditor::PolyButton`, `SpectrogramComponent::LoopButton`) are defined as private nested classes next to the component that owns them, rather than as standalone reusable widgets.

### Presets / History
- `PresetManager` (`Source/PresetManager.h/.cpp`) manages on-disk preset files organized into banks/categories, plus a samples folder; presets serialize the full `apvts` state, region/loop/selection state, and can embed the sample audio itself as base64-encoded WAV (`audioBufferToBase64Wav`/`base64WavToAudioBuffer`) so a preset is self-contained.
- `HistoryManager` (`Source/HistoryManager.h/.cpp`) is an undo/checkpoint stack (`MAX_HISTORY_ITEMS = 10`) storing the same state shape as presets (params, region, loop, selections, sample snapshot) as `HistoryEntry` items on disk; `PluginProcessor::checkpointHistoryState()` is the entry point editors call to push a checkpoint.
- Both persist through the filesystem (`presetsFolder`, `samplesFolder`, `historyFolder`), not just in-memory — expect file I/O when reading this code.

### Parameters
All automatable parameters are declared in one place: `VancespectralAudioProcessor::createParameterLayout()` in `Source/PluginProcessor.cpp`. Parameter IDs are plain strings (e.g. `"AMP_ATTACK"`, `"PLAYBACK_MODE"`, `"PITCH_SEMITONES"`) — when adding a new automatable control, add it there and wire an APVTS attachment in the editor, rather than adding raw engine setters only.
